# Connections model: testing strategy audit

September 30, 2026. Read-only source audit at `39dd2457ace1c8358aa9c954604dfb0e1437d6b0`, with the current CI measurements recorded in the companion reports. No code, tests, workflows, paid CI runs, caches or remote settings changed. This is a focused audit of the Windows Connections model and its surrounding witnesses, not a claim to have audited every Slate test.

## Assessment

The model is meaningful integration coverage. Its size alone does not establish a bad testing strategy. The strongest demonstrated misalignment is **paying repeatedly for a shutdown timeout that is induced by the test's own gate**, while describing that work as comprehensive state coverage. Repair that first while keeping every current cell and assertion. The existing measurements imply a substantial improvement without deleting coverage.

A second, more strategic concern is that the 13,069 count can convey more completeness than it proves. It is an exhaustive execution of a particular hand-defined, fixture-bounded inventory. It is not exhaustive exploration of every product state, command sequence, native computation, UI landing or asynchronous schedule. A smaller fast suite and a larger expensive suite can both miss the same class of defects if they share those boundaries. The next investment should measure detection value and address those boundaries rather than target an arbitrary test-count reduction.

## What the current model earns

| Mechanism | Value and boundary |
| --- | --- |
| Independent derivation | `Derive`, `DeriveReRoot` and `DeriveComposed` predict expected timelines and state from the cell and contract. Actual behavior comes from a real workspace and filesystem `VaultSession`. Expected summary lines come from a separate fixture/session query rather than the workspace's publication. This can detect host orchestration defects without making the host output its own oracle. It delegates native graph/copy correctness to other tests. |
| Deterministic pending work | Loads are parked after their native crossings before a route is driven. The test controls the important happens-before relationship instead of hoping a slow runner encounters a race. Modal-gate cases pump a real dispatcher frame and then introduce specified changes. This is useful concurrency testing. It covers the specified orderings, not all schedules. |
| Broad final checks | The routes compare issued loads, complete ordered timeline, effective root, depth, publication state, retirement, in-flight state, pin, note in view, complete back stack, shared key, pending mount and last focus request. Composed cases also check whether an editor request occurred and how often the dirty gate asked. These are substantially more than snapshots or example rows. |
| Complete/disjoint sharding | Invalid or partial shard configuration fails; a local substring filter cannot produce CI evidence. Each shard enumerates the same complete inventory, then partitions reachable ordinals. The separate verifier rejects missing families, wrong counts, incomplete or overlapping ordinals and different sibling inventories. This protects execution completeness. |
| Independent surrounding layers | Direct leaf tests check epochs, native crossing counts, envelope rejection, cancellation and invalid action admission. Source censuses check trigger ownership, mutation boundaries and dataflow. WPF view tests check peers, chords and retained rows. Real shell/accessibility journeys check actual keyboard landing. These are different failure surfaces even when they mention the same feature. |

## The demonstrated waste and what would preserve the proof

Current reports record **1,439.754 seconds of Shutdown drive time** out of **1,851.423 seconds of aggregate model-family execution**, approximately **77.8%**. The remainder is **411.669 seconds**, about 6m52s across both processes; that is arithmetic on the existing measurements, not an after-repair runtime or a provider billing prediction. The pair's job clocks total 36m31s, so runner setup/build and other non-family costs remain too. [Current measured evidence](namespace-repo-research-2026-09-30.md).

The first-family FOLLOWING arrangement explicitly avoids parking a Shutdown fetch. The pinned arrangement always arms and waits on the gate. The driver then calls `Workspace.Dispose()` synchronously and only releases the gate after the driver returns. `Dispose()` encounters the artificially blocked work and waits its five-second production fallback. There are 288 pinned/in-flight Shutdown cells, accounting for roughly 1,440 seconds by source-derived cardinality. Each still has useful state/retirement assertions; each does not need to exercise the entire fallback timeout. [FOLLOWING gate policy](https://github.com/coryj627/slate/blob/39dd2457ace1c8358aa9c954604dfb0e1437d6b0/apps/slate-windows/tests/SlateWindows.Tests/ConnectionsLeafTests.Model.cs#L1152-L1173), [pinned gate policy](https://github.com/coryj627/slate/blob/39dd2457ace1c8358aa9c954604dfb0e1437d6b0/apps/slate-windows/tests/SlateWindows.Tests/ConnectionsLeafTests.Model.cs#L1422-L1475), [driver and delayed release](https://github.com/coryj627/slate/blob/39dd2457ace1c8358aa9c954604dfb0e1437d6b0/apps/slate-windows/tests/SlateWindows.Tests/ConnectionsLeafTests.Model.cs#L1910-L1912), [release](https://github.com/coryj627/slate/blob/39dd2457ace1c8358aa9c954604dfb0e1437d6b0/apps/slate-windows/tests/SlateWindows.Tests/ConnectionsLeafTests.Model.cs#L2100-L2103), [production bound](https://github.com/coryj627/slate/blob/39dd2457ace1c8358aa9c954604dfb0e1437d6b0/apps/slate-windows/src/SlateWindows/WorkspaceViewModel.cs#L3186-L3200).

Keep all 13,069 cells. Arm a bounded retained helper before owner-thread disposal; observe the leaf's retirement barrier; release the gate after that observation; join the helper and explicitly drain the worker before gate/session disposal. Preserve the production bound and the assertions that retired work cannot publish or speak. Current Shutdown cleanup skips normal settle and disposes its gate/session without that explicit post-release drain, so the repair should strengthen ownership rather than merely make it faster. [Retirement and request invalidation](https://github.com/coryj627/slate/blob/39dd2457ace1c8358aa9c954604dfb0e1437d6b0/apps/slate-windows/src/SlateWindows/Graph/ConnectionsLeafViewModel.cs#L1153-L1174), [current cleanup](https://github.com/coryj627/slate/blob/39dd2457ace1c8358aa9c954604dfb0e1437d6b0/apps/slate-windows/tests/SlateWindows.Tests/ConnectionsLeafTests.Model.cs#L2211-L2221).

Retain separately focused witnesses for the timeout/drain boundary. A six-second rescan test intentionally checks that rescan-originated work drains past the ordinary five-second bound. That wait has an explicit behavioral purpose and occurs in a focused fact; it should not be equated with the Cartesian repeated wait. Review its retained-helper/failure-path ownership too. [Focused extended-drain witness](https://github.com/coryj627/slate/blob/39dd2457ace1c8358aa9c954604dfb0e1437d6b0/apps/slate-windows/tests/SlateWindows.Tests/ConnectionsLeafTests.Rescan.cs#L10-L86).

## Where the strategy could be misaligned

1. **Coverage count can stand in for risk coverage.** The first model family crosses 35 routes with four fixed mode arrangements, pane/leaf states, three roots, five presentations and three pending states. The reroot family uses current presentation and no prior pending load; the composed family covers 49 explicitly selected routes crossed with modes, with the pane visible and leaf active. Fixed stacks have zero, one or two entries in the common arrangement. These are strong finite witnesses, but adding more combinations within them may have less value than deeper command sequences, another completion ordering, different path/topology shapes or actual keyboard landing. That comparison needs evidence rather than assumed equivalence. [Fixed stacks](https://github.com/coryj627/slate/blob/39dd2457ace1c8358aa9c954604dfb0e1437d6b0/apps/slate-windows/tests/SlateWindows.Tests/ConnectionsLeafTests.Model.cs#L359-L373), [reroot arrangement boundary](https://github.com/coryj627/slate/blob/39dd2457ace1c8358aa9c954604dfb0e1437d6b0/apps/slate-windows/tests/SlateWindows.Tests/ConnectionsLeafTests.Model.ReRoot.cs#L185-L191), [composed dimensions](https://github.com/coryj627/slate/blob/39dd2457ace1c8358aa9c954604dfb0e1437d6b0/apps/slate-windows/tests/SlateWindows.Tests/ConnectionsLeafTests.Model.Composed.cs#L9-L94).

2. **The word “unreachable” includes fixture and route-domain limitations.** Examples: the fixture does not link a canvas/base; the pinned tree has no attachment row; Back has no entrance/target dimensions. Those are legitimate reasons not to execute a particular cell. They are not all global impossibilities of the product. Distinguish state impossibility, command refusal, inapplicable dimension and fixture omission when reviewing expansion. Do not treat all 5,216 excluded reroot cells as proof the product can never encounter the corresponding broad situation. [Exclusions](https://github.com/coryj627/slate/blob/39dd2457ace1c8358aa9c954604dfb0e1437d6b0/apps/slate-windows/tests/SlateWindows.Tests/ConnectionsLeafTests.Model.ReRoot.cs#L108-L174).

3. **Running the full host for every policy case is expensive coupling, but it is also the integration guarantee.** Every cell copies files, opens and scans a native session, builds a workspace, arranges state through real commands, pumps tracked work and persists/disposes. A pure state-transition suite could explore more states cheaply, but replacing the existing model with mocks would lose command wiring, native envelope and persistence evidence. A product policy extraction is an architectural change, not a free testing refactor. Only consider it where current responsibilities can actually form a deep module. [Real host](https://github.com/coryj627/slate/blob/39dd2457ace1c8358aa9c954604dfb0e1437d6b0/apps/slate-windows/tests/SlateWindows.Tests/ConnectionsLeafTests.cs#L22-L149), [per-cell setup](https://github.com/coryj627/slate/blob/39dd2457ace1c8358aa9c954604dfb0e1437d6b0/apps/slate-windows/tests/SlateWindows.Tests/ConnectionsLeafTests.Model.cs#L2040-L2103).

4. **The inventory verifier is an execution proof, not an independent semantics proof.** The digest covers cell descriptions, routes, exclusions and order, and is compared between siblings. It does not pin a canonical expected digest or derive correct assertions. Both shards can have the same intentionally or accidentally changed expectations. Counts plus matching digests are excellent protection against partial execution; they are not evidence that a new dimension, route or assertion is semantically sufficient. Keep model changes subject to semantic review and meaningful fault injection. [Digest calculation](https://github.com/coryj627/slate/blob/39dd2457ace1c8358aa9c954604dfb0e1437d6b0/apps/slate-windows/tests/SlateWindows.Tests/ModelTestRun.cs#L80-L107), [verifier trust boundary](https://github.com/coryj627/slate/blob/39dd2457ace1c8358aa9c954604dfb0e1437d6b0/scripts/verify_windows_model_shards.py#L48-L108).

5. **The current timing evidence does not measure marginal coverage value.** Reports aggregate per route and phase. They do not report each cell/dimension's cost, last active cell on a killed process, or which behavioral faults each layer catches. Three large xUnit facts represent the whole model, so a TRX alone cannot provide per-scenario tails. Add bounded durable progress and slow-cell samples, plus a curated fault-detection map before deleting cases or introducing pairwise sampling. [Timing schema](https://github.com/coryj627/slate/blob/39dd2457ace1c8358aa9c954604dfb0e1437d6b0/apps/slate-windows/tests/SlateWindows.Tests/ModelTestRun.cs#L155-L238).

6. **Model focus requests are not actual focus.** Current composed assertions capture the requested boundary and absence/presence of an editor request. The real shown-shell regression exists separately because a correct request can still land on the rail. That regression is a concrete example of a bug the full count cannot rule out. Keep the process/view layer. [Request assertions](https://github.com/coryj627/slate/blob/39dd2457ace1c8358aa9c954604dfb0e1437d6b0/apps/slate-windows/tests/SlateWindows.Tests/ConnectionsLeafTests.Model.Composed.cs#L1153-L1165), [shown-shell landing regression](https://github.com/coryj627/slate/blob/39dd2457ace1c8358aa9c954604dfb0e1437d6b0/apps/slate-windows/tests/SlateWindows.Tests/ConnectionsReRootLandingTests.cs#L13-L78).

## Apparent duplication that should survive this audit

`PinToPushesTheOriginPinsIssuesOneLoadWritesTheKeyAndSpeaksTheLine` additionally checks epoch movement and native stable-key crossings; the Cartesian model checks many workspace routes but not those exact counters. Receiver facts deliberately corrupt envelope fields and lifecycle identity. Source censuses use bound symbols/control-flow evidence to make architectural boundaries closed over all current callers; the model's selected commands cannot prove no extra caller exists. WPF peers and shown-shell tests exercise views absent from the model. The workflow explicitly excludes model facts from the app lane, so the same full census is not being run there again. [Direct leaf details](https://github.com/coryj627/slate/blob/39dd2457ace1c8358aa9c954604dfb0e1437d6b0/apps/slate-windows/tests/SlateWindows.Tests/ConnectionsLeafTests.ReRoot.cs#L23-L56), [receiver rejection/cancellation](https://github.com/coryj627/slate/blob/39dd2457ace1c8358aa9c954604dfb0e1437d6b0/apps/slate-windows/tests/SlateWindows.Tests/ConnectionsLeafTests.Receiver.cs#L99-L274), [architectural census](https://github.com/coryj627/slate/blob/39dd2457ace1c8358aa9c954604dfb0e1437d6b0/apps/slate-windows/tests/SlateWindows.Tests/Censuses/ConnectionsLeafCensus.cs#L92-L112), [app/model separation](https://github.com/coryj627/slate/blob/39dd2457ace1c8358aa9c954604dfb0e1437d6b0/.github/workflows/windows.yml#L444-L446).

Exact owner/file names in a census can make benign structural refactors expensive. That is a maintenance concern worth reviewing per contract, not grounds to discard the architectural invariant. Keep checks for one owned reconciliation/relay path; consider replacing incidental spelling constraints with semantic ownership only where the evidence remains equivalent.

## Safe decision sequence

1. Repair shutdown gate ownership and failure cleanup; run the exact existing census with unchanged semantic assertions and independent reports. Compare cold/warm phase results before altering strategy.
2. Record per-test app cost and bounded model progress/slow-cell evidence. Rank remaining costs by runtime and observed instability, not count.
3. Recreate a small reviewed fault corpus from historical model-only mutations and recent real regressions. For each, record which layer catches it, time to failure, and whether the result survives slower runners. A focused subset is useful only if its unique detection value is known.
4. In parallel with the full suite, prototype additional bounded sequence/schedule tests over root/pin/stack transitions. Use reproducible seeds and minimized failure traces; target uncovered risks such as repeated re-root/Back around rename/delete, deeper stacks and reordered completions. Derive independent expectations and retain selected real-session integration witnesses.
5. Consider a fast policy layer only if the production interface can cleanly expose the relevant transition and invariants without duplicating its implementation. Keep full current integration coverage as the pilot oracle; compare behavior and fault kills before reducing any layer.
6. Review any proposed smaller integration inventory by an explicit implication argument: which removed cells are represented, which inputs/outputs and side effects establish equivalence, which fault corpus verifies the claim, and what remains on exact final commits. Pairwise sampling alone does not establish sufficiency for this multiway lifecycle policy.

Paying $250 can be rational if the measured remaining time improves feedback enough. It would not fix the demonstrated gate-wait waste, the missing marginal-value evidence, or a false impression that the count proves all schedules. It is reasonable to buy capacity after evaluating those issues; it is premature to throw away the model to reach a subscription target.
