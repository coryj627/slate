## Design

1. **The scope, in the model's own words.** A paragraph in the model host's summary (`T/ConnectionsLeafTests.cs:64-66`): the host registers no session listener, so no core event reaches the workspace through the lifecycle. The rename and delete drivers stand in for their own change by hand, with the lifecycle's retarget or invalidation and the graph probe only; the rest of the file-change arm (`ApplyFileChangeEffects`: the missing-tab reseat, the interaction states, Quick Open, the reading and Bases notices, the feed provenance) does not run. The ghost routes deliver nothing for their own `Created`. Events core sends as a side effect are outside the model: a `Modified` for each note whose links a rename rewrote, and a `Modified` for a moved note that a later task query re-reads. The host runs task queries inline, so such a re-read's generation move is seen by the hand-called probe, though its event is not heard. Each kind is named, not counted. `ConnectionsLeafTests.Lifecycle.cs` pins one composed route through the real lifecycle (#1625, CD30).
2. **The two cells.** `RenamePinInDialog` (`Model.Composed.cs:338-346`) and `RenamePinFolderInDialog` (`:347-351`) each gain a sentence: the rename's `Modified` for `hub.md` is not delivered; through the real lifecycle the click-first order gives this derivation exactly and the pool-settled order speaks the tree's line before the failure (the lifecycle fact for the pin; step 0 for the folder).
