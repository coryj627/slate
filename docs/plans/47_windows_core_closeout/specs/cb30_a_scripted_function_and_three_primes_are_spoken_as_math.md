## Goal

A function name with a script after a letter, a number, a minus sign, a closing bracket, a group, a fraction, a root, a script or text (`2\sin^2 x`, `n\log_2 n`, `2\max_i a_i`, `-\sin^2 x`) gets MathCAT's speech and braille, not "Math expression: <source>" with no braille. A function used as an ungrouped script argument (`x_\max`, `T_\min + 1`, `x_\min^\max`) is read exactly as its grouped form (`x_{\max}`) is. Three or more primes after a carrier (`f'''(x)`, `f''''(x)`, `\sin'''(x)`) are spoken as primes on a function ("f triple prime, of x"), while their Nemeth braille and the MathML Windows exposes stay the loose form's, which is right today. No formula that renders today changes its MathML, speech or braille, except the long prime runs' speech.

## Design

### #1629: the writer's extra space leaves a script element

1. **`repair_script_children(mathml: &str) -> String`, a new private function in `C/math.rs`**, run last when a tree is written: `Ok(()) => repair_script_children(&escape_stray_markup(&out))` (after the escape, so every `<` left is markup). It runs on every tree this chunk builds, the loose one and the folded one (Design 6). The rule, for each `msup`, `msub`, `munder` or `mover` (arity 2) and each `msubsup` or `munderover` (arity 3) that has more element children than its arity:
   - the candidates are the children that are exactly `<mspace width="0.1667em" />` and are followed directly by an `<mi` element (the function name the writer spaced);
   - only if removing every candidate leaves exactly the arity is anything changed; otherwise the element is left as written;
   - a candidate that is the element's first child moves to just before the element's open tag (F1: the function was the base, and `2\sin^2 x` reads as `2\sin x` does, a thin space between the atom and the function);
   - a candidate that is a later child is dropped, and so is the application mark the writer put right after the element (`<mo>⁡</mo>`, then the thin space after that mark if one follows) (F2: the function was an argument, so nothing is applied to what follows; Call 2).
2. **The walk is one left-to-right pass over the tags with an explicit stack, never recursive and never a node tree.** The writer, the parser and XB-8's fold are iterative, and a 16 KiB formula (`MAX_FORMULA_SOURCE_BYTES`, `C/math.rs:281`) can nest about 8,000 groups; MathCAT refuses depth past 512 and the formula falls back today. A recursive walk on the `slate-mathcat` thread (default stack, `:495-498`) could overflow, which aborts the process instead (fact 9).
3. **Why it can only change what MathCAT rejects.** An element is touched only when it has more children than its arity, and MathCAT rejects every such element (`canonicalize.rs:638-646`), so no formula MathCAT accepts today changes; the corpus agrees (0 of 212 golden MathMLs change, `corpus.txt`, `round3.txt`). Requiring the space to be followed by an `<mi` and the result to have exactly the arity keeps the rule from making a wrong structure out of an odd one: `\hat\sin^\hspace{0.1667em}(x)` (an authored space after an accented function, whose application mark the writer puts inside the `msup`) is left falling back, where a looser rule turned it into "sine hat, superscript of, of x" (`round2.txt`). The rule finds the writer's space by its bytes, so an authored `\hspace{0.1667em}`, `\kern0.1667em` or `\hskip0.1667em` in the same place is treated the same way (`x\hspace{0.1667em}\sin^2 x` renders "x sine squared of x"); in a slot with the right count it is never touched (`x^\hspace{0.1667em} 2`).
4. **Measured with the prototype** (`family-summary.txt`, `f2.txt`, `round2.txt`, `round3.txt`; the prototype was recursive, the product is not): every F1 and F2 source renders, with no element of the wrong count. ClearSpeak Medium: `2\sin^2 x` "2 sine squared of x" (Nemeth ⠼⠆⠎⠊⠝⠘⠆⠀⠭); `n\log_2 n` "n the log base 2, of n"; `x\log_2^2 n` "x, the log base 2, squared of n"; `-\sin^2 x` "negative sine squared of x"; `2\max_i a_i` "2, max sub i, of eigh sub i"; `2\max\limits_i a_i` "2, max with i below of eigh sub i"; `x_\max` "x sub max end sub"; `x_\max y` "x sub max end sub; y"; `T_\min + 1` "cap t sub min end sub; plus 1"; `x_\min^\max` "x sub min end sub, raised to the max power". For every F2 source the speech under all six settings and the braille under both codes equal its grouped form's (`round2.txt`).
4b. **Design 1b, an accented function as a script's base (the lead's ruling on Call 5).** Step 0 round four (`round4-summary.txt`) measured on main: `2\hat\sin^2 x` is `<msup><mover><mspace/><mi>sin</mi><mi>^</mi></mover><mo>⁡</mo><mspace/><mn>2</mn></msup>`: the accent (`\hat`, `\bar`, `\tilde`, `\overline`, `\widehat`, `\vec`) is a script element of its own, the writer's space lands inside it, and when it closes the writer puts the function's application mark and its space inside the outer element; `\hat\sin^2 x` (no atom before it) fails the same way, and `2\hat\sin x` fails on the accent alone. Each grouped form (`2{\hat\sin}^2 x`) renders. So the rule of Design 1 gains three candidates and two placements, as coded: a thin space the repair moved out from the front of a child (the cascade, so the accent's space leaves both elements); an application mark; a thin space directly after a candidate mark. A mark directly after the base, with its space, moves to just after the element; the writer's own mark after the element then goes, so one remains (`\hat\sin^\max x`). The flag that drops the mark after the element is set only by the writer's space before a function name in an argument slot, not by a space after an inner mark (`\sin^\hat\cos x` keeps `sin`'s mark; the diff's red team found the wider flag reading `\operatorname{foo}^\hat\cos x` wrongly). The exact-arity guard still decides: `\hat\sin^\hspace{0.1667em}(x)` is left as written. Measured with the facts: every accented pair reads as its group under all six speech settings and both codes.
5. **What it leaves falling back** (Call 5, ruled): `\frac x\sin` and `\frac x\sin y` (a fraction, not a script element: the writer's space and, with a term after it, its application mark land inside the `mfrac`; a #1955 line), `\hat\sin^\hspace{0.1667em}(x)` (above), F3's `x^\rm a` (a #1955 line). ### #1628: two trees for a long run of primes (CD21)

8. **The fold takes a mode.** `fold_primes_into_superscripts` gains a parameter saying what a run of three or more primes after a carrier becomes: `Loose` (today: kept as parsed) or `Folded` (a superscript, as one and two are: `‴` for three, `⁗` for four, and for five or more an `mrow` of that many `′`, Call 3). Every other rule of the fold is the same in both modes, so the two trees differ only at long runs after a carrier. The fold reports whether it met such a run; a run with no carrier (`\left(fg\right)'''(x)`, `'''x`) does not count.
9. **Both trees are written the same way.** A private function turns an event stream into MathML (the function-name escape, `push_mathml`, `escape_stray_markup`, `repair_script_children`); `latex_to_mathml` keeps returning the loose string for its callers and tests, and a sibling returns the pair: the loose tree, and the folded tree only when the fold met a long run. For every other formula there is one tree and one `set_mathml`, as today.
10. **`render_math_on_worker` reads speech from the folded tree and braille from the loose tree.** A new `speech_and_braille_from_two_trees` takes the two strings; `mathml_to_speech_and_braille` keeps its one-tree signature and path. The paths, each with a fact (facts 7 and 8):
    - one tree: exactly today's path (one `set_mathml`, speech, braille; a braille failure keeps the speech, #1558; too large is `MathmlTooLarge`);
    - two trees: the speech tree is checked against the 1 MiB cap and set, and its speech read; any failure there (too large, `set_mathml`, `get_spoken_text`) falls back to the one-tree path on the loose tree, so the formula is spoken as it is today; then the loose tree is checked against the cap, set and brailled; a failure there keeps the speech with no braille (#1558's rule); the loose tree too large with the speech read is the same "no braille" case. Only when the loose tree fails on its own one-tree path does the formula fall back to its source, as today.
11. **What it gives, measured** (the probe's split, `primes-summary.txt`, `round2.txt`): `f'''(x)` "f triple prime, of x" in ClearSpeak Medium and "f triple prime, x" in SimpleSpeak Terse, Nemeth ⠋⠄⠄⠄⠷⠭⠾, UEB ⠰⠰⠋⠶⠶⠶⠐⠣⠭⠐⠜ (both the golden's today); the exposed MathML unchanged. `f\trprime(x)` gets the folded speech and keeps main's braille with the stray full stop (Call 4).
12. **The comments say it where a reader looks.** The fold's doc (`:810-837`), `render_math_on_worker`'s, `MathBlock`'s (`:133-135`: a long prime run's speech is read from a folded tree, not from `mathml`), the golden README (`F/README.md`: a long run's pinned speech does not come from the pinned MathML), `extra-expressions.txt:65-67` ("three stay as parsed (#1628)", true now of the MathML and braille only) and `consecutive_primes_fold_into_one_superscript`'s doc (`:1218-1220`) say that a long run is spoken from the folded tree and brailled from the loose one, why (MathCAT 0.7.7's `‴` and `⁗` Nemeth cells, `unicode-full.yaml:686-687`), and that the split goes when a MathCAT release corrects the cells (plan §8's watch row for #1628, which then drops it with one golden diff). The uniffi `MathBlock` doc is not edited (CB-14 holds `lib.rs` in this wave).
13. **What reads the exposed MathML is not changed by this.** Narrator's MathML pipeline and any NVDA reading of the UI Automation MathML property get the loose tree, so by reading they still say "times" for `f'''(x)`.
