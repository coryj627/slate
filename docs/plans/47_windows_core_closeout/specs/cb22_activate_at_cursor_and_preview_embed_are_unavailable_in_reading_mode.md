## Design

1. **The predicates.** Both commands gate on `_tab.IsEditorVisible` (`EI.cs:663`, `:666`). The resolver, the menu bindings and the context menu are untouched: a disabled `RelayCommand` gives the palette `UnavailableReason`, and the menu items dim.

2. **The requery.** A new coordinator member, `internal void EditorSurfaceChanged()`, raises `CanExecuteChanged` on both commands. `WorkspaceTabViewModel.ToggleViewMode` calls `_editorInteractions?.EditorSurfaceChanged()` after its four property notifications (`WVM.cs:485-488`). No other site needs it: the constructor has no subscriber yet, and `ReplaceItem` makes new commands and rebinds (Call 1).

3. **The guard.** One private helper, `EditorHidden`, true when `!_tab.IsEditorVisible`. `ActivateAt`, `ActivateSpan` and `PreviewEmbedAt` each return at once when it is true, after `ThrowIfDisposed()` and before anything is read, queued, logged or said. So both commands, the UIA peer's entry and any later caller are covered, and the guard is silent: no sentence, no diagnostic line, no construction site (Call 2). What each returns: `ActivateAt` and `PreviewEmbedAt` return true, "the press is taken and nothing more is to be done", so a Ctrl+Enter that raced the switch is not passed on to AvalonEdit as a line break in a hidden editor (`S/SlateTextEditor.cs:245-254` passes the key on when it gets false; the red team's finding 11). `ActivateSpan` returns false, as it does for a span that is no longer there, so the UIA peer answers a kept link element as it answers a stale one.

4. **Leaving the editor closes its transient UI.** `EditorSurfaceChanged()` calls `CloseTransientUi()` when the editor is now hidden. That cancels a pending preview, clears the pending citation hover and the three user-requested-load flags, and closes an open popover without asking for focus. Nothing is said. On the way back to the editor it only raises the commands (Call 5).

5. **The pointer operand.** `EI.cs:2048` becomes `EnsureArtifactCacheReady(announceWhenUnavailable: origin is EditorInteractionOrigin.Keyboard)`. For a pointer this silences the loading sentence and the reload sentence, and leaves `_artifactLoadRequestedByUser` unset, so a load that later faults says nothing either. The return value is unchanged: the click is consumed (Calls 3 and 4). The keyboard origin speaks exactly as today. `FollowLink`, `PreviewEmbed` and `ShowCitation` are untouched (Call 6).

6. **Actual Size gets its own access key** (Call 8): `Header="Actual Si_ze"` at `S/MainWindow.xaml:678`. Nothing else in the XAML moves.

What a reader gets. In reading mode, Editor > Activate at Cursor and Editor > Preview Embed are unavailable, and each palette row says "Selected: Activate at Cursor. Unavailable: This command is not available right now." and, on Enter, "This command is not available right now.", with the palette left open. Nothing toggles a task, follows a link or opens a preview from the hidden caret. An interaction popover open at the switch closes, and the keys land on the reading surface. Back in the editor both commands are available again at the next menu open. A Ctrl+click on prose while the note's links and tasks load is silent.

What a reader loses, by CD14: arrowing the Editor menu in reading mode no longer passes the two items, because WPF's arrow keys skip a disabled item (measured). They are still in the menu for a pointer and for a screen reader's object navigation, dimmed.

Not delivered, and said so in the PR: a sentence that says why the two commands are unavailable (CD14 chose the palette's generic sentence); moving the three host-composed interaction sentences into core (CD38's catalogue, an FFI addition).
