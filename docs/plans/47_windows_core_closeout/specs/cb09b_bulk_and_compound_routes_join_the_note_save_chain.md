## Goal

A bulk rename's apply and a tag edit from the Files sidebar take their turn in the note save chain: each waits for every save and operation admitted before it on the notes it may write, and a save of one of those notes asked for while it runs waits for its publication (CD5(a)). Each reconciles the open tabs on the notes it wrote inside its turn, and catches up a tab a rescan or a re-seat had to leave while it held the note. No undo step in a clean tab brings back bytes another writer replaced: not after a property write, a bulk rename, a Bases cell edit, a tag edit or a link rewrite. Close Vault never waits for a whole apply and never disposes the session under one: it cancels the apply first and joins its worker. A link rewrite made by a rename or a move brings every clean open tab on a rewritten note up to the rewritten bytes (CD5(b)). The saved-query export cannot write a note: core refuses any path that does not end in `.base` (CD5(d)). The census ends its four CB-9b rows and is left with five accepted rows (the link rewrites in four members, the Bases export) and one standing row.
