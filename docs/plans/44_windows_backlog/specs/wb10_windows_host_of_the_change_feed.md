## Goal

Today a Windows rescan counts only its own scan's changes: a note another Slate window or `slate-cli` created, edited and deleted is shown after Refresh (tree, Quick Open, tabs, dependents) but Refresh says "Files refreshed. No changes." (AR-30, retired by 21a). After this chunk the run consumes core's change feed: it registers a cursor at the open, opens a window after each scan, applies an exact window's records by path (renames by baseline hash, Quick Open in one pass, dependents narrowed to the window's paths and folder prefixes), falls back to today's full re-sync on a gap or an oversized window with the uncounted sentence, makes up to three passes when the head moved, acknowledges, and speaks the exact cross-session count on an explicit Refresh only (Q2): "Files refreshed. 2 new or changed, 1 removed." Foreground and watcher runs apply the window silently and speak only their own scan's counts.

## Design

**The open.** In the session load (`VaultLifecycleViewModel.cs:536-539`): after `ScanInitialWithProgress`, `activeSession.RegisterChangeFeed()` inside a try that logs a failure as a new `HostDiagnosticEvent.ChangeFeedRegisterFailed` (no path) and continues — the first run's window is then a `Gap` and takes the fallback. Then `LoadSwitcherFiles`. Seam `RegisterChangeFeedForTests`.

**The run** (`RunOneRescanAsync`, after the scan at `:496`). Replace the `ReSyncFromIndexAsync` call with `ConsumeChangeFeedAsync(generation, session, reason, report, cancel, cancellation)` returning `ChangeFeedOutcome { Failed, Counted, Changed, Removed }`:

1. **The journal.** `switcher.BeginReplacement()` moves from `ReSyncQuickOpenAsync :616` to the start of the run and is ended in a `finally` at the run's end.
2. **The retry set** (`HashSet<RescanSurface> _retrySet` on the lifecycle; `RescanSurface`, new, a namespace-level `internal enum` in `VaultLifecycleViewModel.Rescan.cs` that the workspace's collector shares: `Tree`, `QuickOpen`, `Reading`, `History`, `Bases`, `Graph` — the design's "a dependent by its reload", `:660-664`). Every re-sync operation that fails is counted in the run's sentence (AR-66) and puts its surface in the set: the tree refresh → `Tree`; Quick Open's reload, `ApplyRecordsAsync` or journal re-read → `QuickOpen`; a dependent publication that faults or counts a failure → its kind's surface (`reading`, `history`, `bases`, `graph`, the kinds `RescanPublicationForTests` already sees), which `ReSyncDependentsAsync` adds to the run's `failedSurfaces` collector (item 4); a `ReSyncDependentsAsync` that throws whole → all four dependent surfaces. At the run's start the set is copied (`retrying`), and whatever the reason: `Tree` and `QuickOpen` run their full reloads before the first window (R-9's branches), and the four dependent surfaces ride the run's **first** dependents pass as `RescanTouch.Retry` — run **whatever the window holds and independent of the record predicates** (`Reading` → every reading model's `NotifyRescanAsync`, today's ungated rule; `History` → the shown note's reload; `Bases` → `ReSyncBasesAsync` whole; `Graph` → `NotifyGraphOfRescanAsync`). A surface leaves `_retrySet` only when its retry ran and did not fail; a cancelled run leaves the set as it found it; a close or a vault switch clears it. The window is acknowledged even when an operation failed — the failure is owned by the retry set, not by the feed (design `:669-671`). **The recovery set** when `reason == Explicit` (Q8), also independent of the window and the record predicates, even with an empty window: Quick Open's whole list reloads; the tree's failure state refetches (`FilesSidebarViewModel.ShowsFailedLevelForRescan`, new); and the first dependents pass carries `RescanTouch.Recover`, which re-checks every dependent showing a failure state — each reading model whose `LastRefreshFailed` re-projects (`NotifyRescanAsync`), History reloads when `History.LoadError is not null`, the Bases branch runs when an open base document is `BaseLoadState.Failed` or a dashboard holds a `DashboardSectionState.Failed` section (its `RefreshAsync` reopens a Failed base, `BaseDocumentViewModel.cs:974`), and the graph probe always runs (the probe is the re-check: it reloads an Error or STALE Connections leaf, and `TheGraphProbesAfterARescan` pins one probe on an unchanged Refresh). A board's load error needs no entry: the tab comparison re-checks it every run.
3. **The window.** `ulong? after = null; for (pass = 1; pass <= SlateUniffiMethods.ChangeFeedMaxPasses(); pass++)`: `window = await RunRescanCoreAsync("window", () => session.ChangeFeedWindow(after, cancel))`; a thrown feed read is one failure, `answered = false`, the full re-sync runs, break. `Exact` → the record path; `TooLarge` or `Gap` → `ReSyncFromIndexAsync` (today's `:533`, now the fallback; its `ReSyncWorkspaceAsync` passes `touch: null` — today's ungated dependents pass, which subsumes the retry and recovery sets — and the run's `failedSurfaces` collector). After either: `RereadJournalAsync` (every journaled path's `GetFileSummary` through the seam → `QuickSwitcher.ApplyJournaledPathAsync`). Then, when `answered && pass < passes`: `head = session.ChangeFeedHead(cancel)`; break unless `head > window.ToSeq`; `after = window.ToSeq`.
4. **The record path** (`ApplyChangeFeedWindowAsync`), in two phases because renames precede removals in page order: **Phase A, every page** — `session.ChangeFeedPage(window.Token, cursor, Math.Min(1000, MaxChangeFeedPageLimit()), cancel)` on the seam (`ChangeFeedPageLimitForTests` shrinks it); per page, on the dispatcher: `Removed` and `Present` records → `QuickSwitcher.ApplyRecordsAsync(page)` (new; one pass over a `Dictionary<string, int>` path index, `Removed` drops, `Present` with `Openable` upserts from `Summary`); `Renamed` records are appended to `List<ChangeRecord> renames` (bounded by the window's `record_count`, at most 10,000 — never applied yet); every `Removed` path joins `HashSet<string> removed` (the whole window's, accumulated across pages); every record's `Path` (and `RenamedFrom`) joins `HashSet<string> touched`; a `Directory` record's old and new paths join `HashSet<string> touchedPrefixes`; `anyRecord = window.RecordCount > 0`. **Phase B, after the last page** — for each buffered rename, `workspace.RetargetPathForFeedRename(from, to, fromHash, oldIsGone: removed.Contains(from))` (new; below), so `oldIsGone` is decided over the complete window, whatever page the removal came on. Then `ReSyncWorkspaceAsync(workspace, session, cancel, cancellation, touch)` — the existing method (`:655`) gains the `touch` parameter; its hash read and `ReSyncOpenDocumentsAsync` over every open tab are unchanged, and it stays `ReSyncDependentsAsync`'s one call site, so `TheRescanGraphProbeHasOneCallSite` stays green — with `touch = new RescanTouch(touched, touchedPrefixes, anyRecord, retry, recover)` (new record on `WorkspaceViewModel`; `retry` is the run's copied retry set and `recover` is `reason == Explicit`, both on the run's first dependents pass only — empty and false on later passes). `ReSyncDependentsAsync(documents, indexed, cancellation, RescanTouch? touch = null, ISet<RescanSurface>? failedSurfaces = null)` (two new optional parameters; `null` is today's ungated pass, so the fallback and the existing direct callers — `RescanTests.Round3.cs:321`, `ConnectionsLeafTests.Rescan.cs:47`, `:140`, `:240` — keep their meaning; the return stays the failure count): a reading model is notified when any of its `_publishedEmbedDependencies` equals a touched path **or lies under a touched prefix** (`dep.StartsWith(prefix + "/")`), or `_publishedHasUnresolvedEmbeds` and a record is `Created`, or `_publishedHasBaseEmbeds` and `anyRecord`, or its own tab reloaded, **or `Reading` is in `touch.Retry`, or `touch.Recover` and its `LastRefreshFailed`**; History reloads when `HistoryNoteChanged` or its path is touched (exactly or by prefix), **or `History` is in `touch.Retry`, or `touch.Recover` and `History.LoadError is not null`**; **the Bases re-run runs whenever `anyRecord`, or `Bases` is in `touch.Retry`, or `touch.Recover` and a base or a dashboard section shows `Failed`; the graph probe runs whenever `anyRecord`, or `Graph` is in `touch.Retry`, or `touch.Recover`** — `anyRecord` is the same trigger WB-10a drops the graph on, directory-only windows included; then, once, the tree's `RefreshForRescanAsync` when `anyRecord` (silent). A branch that fails is counted (AR-66) and puts its surface into `_retrySet` (item 2). A window with no records touches nothing but the tab comparison, the run's retried surfaces and, on an explicit Refresh, the recovery set.
5. **Acknowledge.** `if (answered && last is not null) session.AcknowledgeChangeFeed(last.Token, cancel)` on the seam; a failure is one error and `answered = false`. Not acknowledged when the run was cancelled (`generation != _generation || cancellation.IsCancellationRequested` — return before the acknowledgment, as the mac returns nil); the session's cursor then stays, and that session's next run reads the same window again.
6. **The sentence** (`:505-519` rewritten per design §4.7 under Q2): `VaultRescanIncomplete(errors)` when `!report.Complete || outcome.Failed > 0`; Explicit with `outcome.Counted` → `VaultRescanFinished(Explicit, outcome.Changed, outcome.Removed)`; Explicit otherwise → `VaultRescanFinishedUncounted(Explicit, report.FilesChanged, report.FilesRemoved)`; Foreground or Watcher → today's rule over the scan's own counts, and the uncounted variant only when the window was not exact and the scan's own counts are non-zero. `outcome.Counted` is true only when the last window was acknowledged, `Exact` and `Counted` (the mac's rule). `PostRescanOutcome`'s watcher gate is unchanged.

**`RetargetPathForFeedRename(from, to, fromHash, oldIsGone)`** on `WorkspaceViewModel` (new, beside `:2844`): for every path-backed tab at `from`: a loaded Markdown tab moves only when `_editorSession.SavedBaseline.ContentHash == fromHash` (a dirty one keeps its buffer, as `RetargetPath` does today); a tab not loaded since it opened moves only when `oldIsGone`; a board or base tab moves as `RetargetPath` moves it; closed-tab entries follow the moved ones. The old `RetargetPath` stays for Slate's own events.

**Not changed:** the scan, `ReSyncFromIndexAsync`'s three branches (now the fallback; its `ReSyncWorkspaceAsync` call gains only `touch: null` and the run's `failedSurfaces` collector), `ReSyncOpenDocumentsAsync`, the watcher's listener and gate, `PostRescanOutcome`, `A11yEvent` (no new variant), the FFI.
