## Goal

Today a Windows rescan counts only its own scan's changes: a note another Slate window or `slate-cli` created, edited and deleted is shown after Refresh (tree, Quick Open, tabs, dependents) but Refresh says "Files refreshed. No changes." (AR-30, retired by 21a). After this chunk the run consumes core's change feed: it registers a cursor at the open, opens a window after each scan, applies an exact window's records by path (renames by baseline hash, Quick Open in one pass, dependents narrowed to the window's paths), falls back to today's full re-sync on a gap or an oversized window with the uncounted sentence, makes up to three passes when the head moved, acknowledges, and speaks the exact cross-session count on an explicit Refresh only (Q2): "Files refreshed. 2 new or changed, 1 removed." Foreground and watcher runs apply the window silently and speak only their own scan's counts.

## Design

**The open.** In the session load (`VaultLifecycleViewModel.cs:536-539`): after `ScanInitialWithProgress`, `activeSession.RegisterChangeFeed()` inside a try that logs a failure as a new `HostDiagnosticEvent.ChangeFeedRegisterFailed` (no path, the #507 rule) and continues — the first run's window is then a `Gap` and takes the fallback (the mac's rule, contract 40 `:27`). Then `LoadSwitcherFiles`. A test seam `RegisterChangeFeedForTests` mirrors `SwitcherPageLoadingForTests`.

**The run** (`RunOneRescanAsync`, after the scan at `:496`). Replace the single `ReSyncFromIndexAsync` call with `ConsumeChangeFeedAsync(generation, session, reason, report, cancel, cancellation)` returning `ChangeFeedOutcome { Failed, Counted, Changed, Removed }`:

1. **The journal.** `switcher.BeginReplacement()` moves from `ReSyncQuickOpenAsync :616` to the start of the run and is ended in a `finally` at the run's end; `JournalChange` keeps recording every Slate-owned event's path (a rename's both).
2. **The retry set** (`HashSet<RescanSurface> _retrySet` on the lifecycle: `Tree`, `QuickOpen`): each surface in the set runs its full reload (`ReSyncTreeAsync`, today's `ReSyncQuickOpenAsync` body minus the journal lines) before the window. **The recovery set** when `reason == Explicit` (Q8): Quick Open's whole list reloads, and the tree's failure state refetches (`FilesSidebarViewModel` exposes `ShowsFailedLevelForRescan`, new, mirroring the mac's), even with an empty window. The failed-surface re-checks of the Bases dock and the graph already happen in `ReSyncDependentsAsync`'s Bases and graph steps, which run on every window with records and on every Explicit run.
3. **The window.** `ulong? after = null; for (pass = 1; pass <= SlateUniffiMethods.ChangeFeedMaxPasses(); pass++)`: `window = await RunRescanCoreAsync("window", () => session.ChangeFeedWindow(after, cancel))`; a thrown feed read is one failure, `answered = false`, the full re-sync runs, break. `Exact` → the record path; `TooLarge` or `Gap` → `ReSyncFromIndexAsync` unchanged (today's `:533`, now the fallback). After either: `RereadJournalAsync` (every journaled path's `GetFileSummary` through the seam → `QuickSwitcher.ApplyJournaledPathAsync`). Then, when `answered && pass < passes`: `head = session.ChangeFeedHead(cancel)`; break unless `head > window.ToSeq`; `after = window.ToSeq`.
4. **The record path** (`ApplyChangeFeedWindowAsync`): pages of `Math.Min(1000, MaxChangeFeedPageLimit())` (`ChangeFeedPageLimitForTests` to shrink it), each `session.ChangeFeedPage(window.Token, cursor, limit, cancel)` on the seam; per page, on the dispatcher: `Renamed` records → `workspace.RetargetPathForFeedRename(from, to, fromHash, oldIsGone)` (new; below); `Removed` and `Present` → `QuickSwitcher.ApplyRecordsAsync(page)` (new; one pass over a `Dictionary<string, int>` path index, `Removed` drops, `Present` with `Openable` upserts from `Summary`, never `Applied`'s per-change array copy); the window's paths accumulate into `HashSet<string> touched` with a flag `anyFileRecord` and `anyStructural` (a Created/Removed/Renamed/Directory record). After the last page: `ReSyncWorkspaceAsync`'s tab comparison as today (`ReSyncOpenDocumentsAsync` over every open tab, unchanged), then `ReSyncDependentsAsync(documents, indexed, cancellation, touched)` (new parameter): reading models get `NotifyRescanAsync(touched, cancellation)` (new overload: re-project when `touched` overlaps `_publishedEmbedDependencies`, or `_publishedHasUnresolvedEmbeds` and a record is `Created`, or `_publishedHasBaseEmbeds` and any file record exists, or the model's own tab reloaded); History reloads when `HistoryNoteChanged` or `touched` contains its path; Bases and the graph probe run when `anyFileRecord`; then, once, the tree's `RefreshForRescanAsync` when the window had any record (silent). A branch that fails is counted (AR-66) and puts `Tree` or `QuickOpen` into `_retrySet`. A window with no records touches nothing but the tab comparison.
5. **Acknowledge.** `if (answered && last is not null) session.AcknowledgeChangeFeed(last.Token, cancel)` on the seam; a failure is one error and `answered = false`. Not acknowledged when the run was cancelled (a close or a vault switch: `generation != _generation || cancellation.IsCancellationRequested` — return before the acknowledgment, as the mac returns nil).
6. **The sentence** (`:505-519` rewritten per design §4.7 under Q2): `VaultRescanIncomplete(errors)` when `!report.Complete || outcome.Failed > 0` (the feed's failures counted with the re-sync's); Explicit with `outcome.Counted` → `VaultRescanFinished(Explicit, outcome.Changed, outcome.Removed)`; Explicit otherwise (a gap, too large, uncounted, or unanswered) → `VaultRescanFinishedUncounted(Explicit, report.FilesChanged, report.FilesRemoved)`; Foreground or Watcher → today's rule over the scan's own counts (`VaultRescanFinished` only when `FilesChanged + FilesRemoved > 0`), and the uncounted variant only when the window was not exact and the scan's own counts are non-zero. `PostRescanOutcome`'s watcher gate is unchanged.

**`RetargetPathForFeedRename(from, to, fromHash, oldIsGone)`** on `WorkspaceViewModel` (new, beside `:2844`): for every path-backed tab at `from`: a loaded Markdown tab moves only when `_editorSession.SavedBaseline.ContentHash == fromHash` (a dirty one keeps its buffer, as `RetargetPath` does today); a tab not loaded since it opened moves only when `oldIsGone` (the record set holds a `Removed` for `from`); a board or base tab moves as `RetargetPath` moves it (no baseline); closed-tab entries follow the moved ones. The old `RetargetPath` stays for Slate's own events. `oldIsGone` is computed per page from the `Removed` records of the same window (pages are removal-first across boundaries, design `:611-612`, so a rename's `Removed` for its origin precedes or shares its page — verify with `pages_are_bounded_removal_first_and_resume_by_keyset`; if a rename can precede its origin's removal in page order, buffer `Renamed` records until the page that carries the removal or the window's end).

**Not changed:** the scan, `ReSyncFromIndexAsync`'s three branches (now the fallback), `ReSyncOpenDocumentsAsync`, the watcher's listener and gate, `PostRescanOutcome`, `A11yEvent` (no new variant; `VaultRescanFinishedUncounted` exists), the FFI.
