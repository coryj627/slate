## Goal

Today a Windows rescan counts only its own scan's changes: a note another Slate window or `slate-cli` created, edited and deleted is shown after Refresh (tree, Quick Open, tabs, dependents) but Refresh says "Files refreshed. No changes." (AR-30, retired by 21a). After this chunk the run consumes core's change feed: it registers a cursor at the open, opens a window after each scan, applies an exact window's records by path (renames by baseline hash, Quick Open in one pass, dependents narrowed to the window's paths and folder prefixes), falls back to today's full re-sync on a gap or an oversized window with the uncounted sentence, makes up to three passes when the head moved, acknowledges, and speaks the exact cross-session count on an explicit Refresh only (Q2): "Files refreshed. 2 new or changed, 1 removed." Foreground and watcher runs apply the window silently and speak only their own scan's counts.

## Design

**The open.** In the session load (`VaultLifecycleViewModel.cs:536-539`): after `ScanInitialWithProgress`, `activeSession.RegisterChangeFeed()` inside a try that logs a failure as a new `HostDiagnosticEvent.ChangeFeedRegisterFailed` (no path) and continues — the first run's window is then a `Gap` and takes the fallback. Then `LoadSwitcherFiles`. Seam `RegisterChangeFeedForTests`.

**The run** (`RunOneRescanAsync`, after the scan at `:496`). Replace the `ReSyncFromIndexAsync` call with `ConsumeChangeFeedAsync(generation, session, reason, report, cancel, cancellation)` returning `ChangeFeedOutcome { Failed, Counted, Changed, Removed }`:

1. **The journal.** `switcher.BeginReplacement()` moves from `ReSyncQuickOpenAsync :616` to the start of the run and is ended in a `finally` at the run's end.
2. **The retry set** (`HashSet<RescanSurface> _retrySet` on the lifecycle: `Tree`, `QuickOpen`): each surface in the set runs its full reload before the window. **The recovery set** when `reason == Explicit` (Q8): Quick Open's whole list reloads, and the tree's failure state refetches (`FilesSidebarViewModel.ShowsFailedLevelForRescan`, new), even with an empty window; the Bases dock and graph re-checks already run in `ReSyncDependentsAsync`.
3. **The window.** `ulong? after = null; for (pass = 1; pass <= SlateUniffiMethods.ChangeFeedMaxPasses(); pass++)`: `window = await RunRescanCoreAsync("window", () => session.ChangeFeedWindow(after, cancel))`; a thrown feed read is one failure, `answered = false`, the full re-sync runs, break. `Exact` → the record path; `TooLarge` or `Gap` → `ReSyncFromIndexAsync` unchanged (today's `:533`, now the fallback). After either: `RereadJournalAsync` (every journaled path's `GetFileSummary` through the seam → `QuickSwitcher.ApplyJournaledPathAsync`). Then, when `answered && pass < passes`: `head = session.ChangeFeedHead(cancel)`; break unless `head > window.ToSeq`; `after = window.ToSeq`.
4. **The record path** (`ApplyChangeFeedWindowAsync`), in two phases because renames precede removals in page order: **Phase A, every page** — `session.ChangeFeedPage(window.Token, cursor, Math.Min(1000, MaxChangeFeedPageLimit()), cancel)` on the seam (`ChangeFeedPageLimitForTests` shrinks it); per page, on the dispatcher: `Removed` and `Present` records → `QuickSwitcher.ApplyRecordsAsync(page)` (new; one pass over a `Dictionary<string, int>` path index, `Removed` drops, `Present` with `Openable` upserts from `Summary`); `Renamed` records are appended to `List<ChangeRecord> renames` (bounded by the window's `record_count`, at most 10,000 — never applied yet); every `Removed` path joins `HashSet<string> removed` (the whole window's, accumulated across pages); every record's `Path` (and `RenamedFrom`) joins `HashSet<string> touched`; a `Directory` record's old and new paths join `HashSet<string> touchedPrefixes`; `anyRecord = window.RecordCount > 0`. **Phase B, after the last page** — for each buffered rename, `workspace.RetargetPathForFeedRename(from, to, fromHash, oldIsGone: removed.Contains(from))` (new; below), so `oldIsGone` is decided over the complete window, whatever page the removal came on. Then `ReSyncWorkspaceAsync`'s tab comparison as today (`ReSyncOpenDocumentsAsync` over every open tab, unchanged), then `ReSyncDependentsAsync(documents, indexed, cancellation, new RescanTouch(touched, touchedPrefixes, anyRecord))` (new parameter): a reading model is notified when any of its `_publishedEmbedDependencies` equals a touched path **or lies under a touched prefix** (`dep.StartsWith(prefix + "/")`), or `_publishedHasUnresolvedEmbeds` and a record is `Created`, or `_publishedHasBaseEmbeds` and `anyRecord`, or its own tab reloaded; History reloads when `HistoryNoteChanged` or its path is touched (exactly or by prefix); **the Bases re-run and the graph probe run whenever `anyRecord`** — the same trigger WB-10a drops the graph on, directory-only windows included; then, once, the tree's `RefreshForRescanAsync` when `anyRecord` (silent). A branch that fails is counted (AR-66) and puts `Tree` or `QuickOpen` into `_retrySet`. A window with no records touches nothing but the tab comparison.
5. **Acknowledge.** `if (answered && last is not null) session.AcknowledgeChangeFeed(last.Token, cancel)` on the seam; a failure is one error and `answered = false`. Not acknowledged when the run was cancelled (`generation != _generation || cancellation.IsCancellationRequested` — return before the acknowledgment, as the mac returns nil); the session's cursor then stays, and that session's next run reads the same window again.
6. **The sentence** (`:505-519` rewritten per design §4.7 under Q2): `VaultRescanIncomplete(errors)` when `!report.Complete || outcome.Failed > 0`; Explicit with `outcome.Counted` → `VaultRescanFinished(Explicit, outcome.Changed, outcome.Removed)`; Explicit otherwise → `VaultRescanFinishedUncounted(Explicit, report.FilesChanged, report.FilesRemoved)`; Foreground or Watcher → today's rule over the scan's own counts, and the uncounted variant only when the window was not exact and the scan's own counts are non-zero. `outcome.Counted` is true only when the last window was acknowledged, `Exact` and `Counted` (the mac's rule). `PostRescanOutcome`'s watcher gate is unchanged.

**`RetargetPathForFeedRename(from, to, fromHash, oldIsGone)`** on `WorkspaceViewModel` (new, beside `:2844`): for every path-backed tab at `from`: a loaded Markdown tab moves only when `_editorSession.SavedBaseline.ContentHash == fromHash` (a dirty one keeps its buffer, as `RetargetPath` does today); a tab not loaded since it opened moves only when `oldIsGone`; a board or base tab moves as `RetargetPath` moves it; closed-tab entries follow the moved ones. The old `RetargetPath` stays for Slate's own events.

**Not changed:** the scan, `ReSyncFromIndexAsync`'s three branches (now the fallback), `ReSyncOpenDocumentsAsync`, the watcher's listener and gate, `PostRescanOutcome`, `A11yEvent` (no new variant), the FFI.
