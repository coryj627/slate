Grid-row and tab distinguishers (vault-relative paths) are reviewed and left as they are; the PR body records why (they are already the shortest unique form inside a vault).
- **#1305.** Neither dispatcher idleness nor a fixed timer marks the end of a sweep. WPF's dispatcher goes idle between two key-repeat messages, so an `ApplicationIdle` post would still run History's destructive reveal reset on every pass; and a fixed interval can elapse before the first repeat arrives (500 ms on this machine), so a timer restarted per arrow would settle on the first row — reloading History there and writing the workspace — and then the held sweep would begin. The settle is defined by the key, never by the clock alone: **it never runs while a rail arrow is held**, and it completes when the last held rail arrow is released or when focus leaves the rail.
  - **New** `internal sealed class RailSettle : IDisposable` (`src/SlateWindows/RailSettle.cs`), owned by `WorkspaceViewModel` as **new** `internal RailSettle RailSettle { get; }`, with **new** `internal RailSettle(Dispatcher dispatcher, Func<TimeSpan> pollInterval, Func<Key, bool> isKeyDown, Action<WorkspaceLeafOption> settled)`. It keeps the set of rail arrows currently down and the leaf an arrow chose:
    - **new** `internal void Pressed(Key key)` adds `key` to the held set (the first press and every auto-repeat);
    - **new** `internal void Arm(WorkspaceLeafOption leaf)` records `leaf` and starts the poll timer if it is not running;
    - **new** `internal void Released(Key key)` removes `key`; when the held set is then empty and a leaf is armed, it settles at once;
    - **new** `internal void FocusLeft()` clears the held set and, when a leaf is armed, settles at once;
    - the poll timer (a `DispatcherTimer`, interval `pollInterval()`, 250 ms by default) is only a backstop for a release the rail never saw: each tick drops every held key `isKeyDown` reports up, counts a tick that still found a key down (**new** `internal int HeldTicksForTests`), and settles only when the held set is empty;
    - `Dispose()` is **teardown, never a settle**: it stops the poll timer, clears the held set and disarms **without** calling `settled`; afterwards `Pressed`, `Arm`, `Released`, `FocusLeft` and a tick do nothing (the window can outlive the workspace and still forward rail keys to it); **new** `internal bool IsArmed` and `internal bool IsHeld` report the state. There is no `Flush`: the one durable effect of a settle, the write, is the workspace's own final `Persist()` on close (below), and History's reload and the queries refresh have no reader on a closing workspace.
    Settling stops the timer, disarms, and calls `settled(leaf)` exactly once.
  - **New** `private void OnLeafSettled(WorkspaceLeafOption leaf)` on `WorkspaceViewModel` performs the deferred work once — `RefreshBaseQueries()` for `queries`, `History.Reload()` for `history`, and the coalesced `Persist()` — only if `ActiveLeaf` is still `leaf` (a non-arrow route that chose another leaf meanwhile already did its own work synchronously) and the workspace is not disposed (`_workspaceDisposed`, a second line behind the teardown). Test counters (**new**, test-only): `internal Action<WorkspaceSnapshot>? PersistedForTests` on `WorkspaceViewModel`, invoked in `PersistCore` after `_persistence.Save` returns; `internal int ReloadCountForTests` on `HistoryViewModel`, incremented at the top of `Reload()`; `internal int BaseQueriesRefreshCountForTests` on `WorkspaceViewModel`, incremented at the top of `RefreshBaseQueries()`.
