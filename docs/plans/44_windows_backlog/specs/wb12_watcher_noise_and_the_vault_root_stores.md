## Goal

Four small truths. A folder's own "modified" notification (NTFS updates a folder's entry lazily when a handle closes) starts a silent Watcher rescan although nothing the scanner reads changed; core drops it (#1516). A Bases export saved inside the open vault is the one host-side write into the vault, so the watcher's run speaks "Files refreshed. 1 new or changed, 0 removed." a second after "Exported."; written through core it is an echo and one sentence (#1508). `GraphConfigStore.Write` recreates a renamed vault's old root; through `AnchoredVaultStore` it refuses and logs (#1475 bullet 1). A pin whose note is gone stays in `sidebar.json` forever on Windows; mac prunes lazily on a level fetch, and Windows now does the same, safely (#1505). And when a recent vault's folder holds nothing but `.slate`, Open Recent says so in observable terms rather than opening an empty vault (WD7).

## Design

**#1516 (core).** In `translate`'s per-path arm (`:661-665`), only a **non-rename** modify of an existing directory is dropped: the new guard matches `EventKind::Modify(ModifyKind::Any | ModifyKind::Data(_) | ModifyKind::Metadata(_) | ModifyKind::Other)` **and never `ModifyKind::Name(_)`**, and drops the event when `std::fs::symlink_metadata(path).map(|m| m.is_dir()).unwrap_or(false)`. Every `Name` variant — `From`, `To`, `Any`, and a `Both` the `:644-650` arm did not take because one side is hidden or outside — still becomes `Modified` for a visible directory, so a one-sided or partially visible folder rename still starts its rescan. `Create`, `Remove`, root changes and a `Modify` whose path is missing (the stat errs) are untouched, so the synthetic tests over the non-existent `root()` keep passing. The stat runs on the coalescer thread (one `symlink_metadata` per event, the same cost class as `classify`'s `long_spelling`).

**#1508 (WD5).** The overwrite question is settled **before** the design is final, by a core fact: `save_text_on_a_non_markdown_path` in `session/tests/` pins whether `save_text("export.csv", text, Some(hash))` is accepted. Then `WorkspaceViewModel.Bases.cs:681-700`: after the dialog, `if (VaultPaths.IsInside(_vaultRoot, targetPath))` (new shared helper lifted from `FilesSidebarViewModel.Import.IsInsideVault`, `:378-388`, used by both) the write goes through core on a worker, **conflict-checked and atomic, never delete-then-create**: (a) `_session.CreateExclusiveBytes(relative, bytes)`; (b) on `VaultException.DestinationExists` — the dialog confirmed an overwrite — read the destination's current hash first (`GetFileSummary(relative).ContentHash`, the hash the user saw when confirming) and replace under it: `SaveText(relative, text, expectedHash)` where `save_text` accepts the path, otherwise a **new core method** `replace_file_bytes(relative, bytes, expected_hash: Option<String>) -> Result<(), VaultError>` (FFI twin `ReplaceFileBytes`), implemented on the existing staged path (`PinnedMutationTarget::publish_staged`, `fs.rs:1178-1210`: stage, sync, publish with `ReplaceIfExists`) inside one index transaction under the Write scope (`ChangeFeedSeat::write_scope`, so it is this session's own write and an echo for the watcher), refusing with `VaultException.WriteConflict` when the index hash differs from `expected_hash` and leaving the destination untouched when staging or publishing fails. Outside the vault: `File.WriteAllText` as today. Failures map to `BasesViewExportFailed(message)`; a `WriteConflict` says the file changed since the confirmation. The watcher then sees an echo and the Slate-owned `Created`/`Modified` event refreshes the tree. Both bindings regenerate if the core method is added (plan §4: never a dylib with mismatched bindings); the new method is a sibling, so mac compiles untouched.

**#1475 bullet 1 (WD7, first half).** `GraphConfigStore.Write` opens `AnchoredVaultStore.Open(_vaultRoot, createDirectory: true)` (keep the root in the ctor beside `_path`), reads the existing file through `ReadAllBytesBounded("graph.json", MaxReadBytes)` (absent → null, as today's `FileNotFoundException` arm), encodes through `GraphConfigEncode(config, existing)` and writes with `WriteAtomically("graph.json", bytes)`; a gone root throws `DirectoryNotFoundException`, which `GraphConfigWriter.Write`'s `IOException` arm already logs as `GraphConfigPersistFailed`. `Directory.CreateDirectory` is gone. `ReadExistingForTests` keeps its seam. Not changed: the read path, the writer's coalescing, the identity comparison (22W, WB-28).

**#1505 (WD6) — the safe prune.** `LoadDirectoryLevel` returns, for a complete level (`!truncated` and the provider page not truncated), `StalePinnedPaths`: the folder's pins (`_pinned` filtered by `ParentPath == parentPath`) not among the listed paths. `FilesSidebarViewModel.PruneStalePins(folder, stale)` runs after the level publishes and is skipped when `_settingsStore?.ReadOnlyReason is not null`, `_pinsBehindFile`, the folder is in the per-session `_prunedFolders`, or a prune for it is in flight; candidates are deduplicated and capped at `MaxPinsPerFolder`. It captures `_pinGeneration` (new, bumped on every change to `_pinned`) and runs on a worker. **Absence is proved by an error-aware probe**, new `VaultAbsence.IsDefinitelyAbsent(root, relative)`: walk the ancestors from the vault root downward (never statting the missing leaf first); for each existing component read its attributes (`File.GetAttributes`, which throws on access and I/O errors — any exception means "not definite", never absent); refuse when any component is a reparse point; the first component that is missing proves the leaf absent **only** when its parent is a plain directory whose `Directory.EnumerateFileSystemEntries` succeeded and does not contain that name (ordinal-ignore-case on NTFS). Inaccessible, erroring or reparse-crossing candidates are kept. **The mutation re-validates under the store lock**: a new `SidebarSettingsStore.PruneStalePins(folder, candidates, Func<string, bool> isDefinitelyAbsent)` runs inside `Update`'s locked mutation (`:246-270`) and removes only candidates still present in the file's pins **and still `isDefinitelyAbsent` at that moment** (the probe runs again under the lock, as mac re-checks ENOENT at mutation time); back on the dispatcher, the pins the store actually removed leave `_pinned` only if `_pinGeneration` is unchanged since the capture (otherwise the result is discarded and the folder stays eligible); `PinsLandedInFile()` as `PersistPins` does; the folder joins `_prunedFolders` only when the store removed something. Nothing is spoken. The write journal is not involved (its entries are renames; a prune is idempotent).

**WD7 (second half).** `OpenRecentAsync`: when `Directory.Exists(recent.Path)` and the folder's top level holds nothing but `.slate` (one `EnumerateFileSystemEntries` pass that stops at the first entry not named `.slate`), the open does not proceed: `ReportTerminalStatus("This folder holds only Slate's data (.slate); the vault's files are not here: {path}", High)` — the same route as "Vault not found: …" at `:740` — and the recents entry is kept.
