## Goal

Four small truths. A folder's own "modified" notification (NTFS updates a folder's entry lazily when a handle closes) starts a silent Watcher rescan although nothing the scanner reads changed; core drops it (#1516). A Bases export saved inside the open vault is the one host-side write into the vault, so the watcher's run speaks "Files refreshed. 1 new or changed, 0 removed." a second after "Exported."; written through core it is an echo and one sentence (#1508). `GraphConfigStore.Write` recreates a renamed vault's old root; through `AnchoredVaultStore` it refuses and logs (#1475 bullet 1). A pin whose note is gone stays in `sidebar.json` forever on Windows; mac prunes lazily on a level fetch, and Windows now does the same (#1505). And when a recent vault's folder holds nothing but `.slate`, Open Recent says so in observable terms rather than opening an empty vault (WD7).

## Design

**#1516 (core).** In `translate`'s per-path arm (`:661-665`): a `Modify(_)` kind whose path `std::fs::symlink_metadata(path).map(|m| m.is_dir()).unwrap_or(false)` is dropped — an existing directory's own modify changes nothing the scanner reads; its entries arrive as their own events. `Create`, `Remove`, `Name` (renames) and root changes are untouched; a `Modify` whose path is missing (`symlink_metadata` errs) stays `Modified`, so the synthetic tests over the non-existent `root()` are unaffected and a folder deleted between event and check still reaches the sink. The stat runs on the coalescer thread (one `symlink_metadata` per event, the same cost class as `classify`'s `long_spelling`). Not changed: `classify`, `need_rescan`, the echo ledger (the event never reaches it now).

**#1508 (WD5).** `WorkspaceViewModel.Bases.cs:681-700`: after the dialog, `if (IsInsideVault(targetPath))` (lift `FilesSidebarViewModel.Import.IsInsideVault`'s rule into a shared `VaultPaths.IsInside(root, absolute)` helper, new, used by both) compute the vault-relative path and write through core on a worker: `_session.CreateExclusiveBytes(relative, bytes)`; on `VaultException.DestinationExists` (the file exists and the dialog already confirmed the overwrite) `_session.SaveText(relative, text, null)` for a `.md` target; for a `.csv` target, if `save_text` refuses a non-Markdown path, the existing file is replaced through the provider's delete-then-create (`DeleteFile` then `CreateExclusiveBytes`; two Slate-owned events, both echoes) — pin which with a fact against core first (`save_text` on `.csv`) and record the answer in the PR body. Outside the vault: `File.WriteAllText` as today. Failures map to `BasesViewExportFailed(message)` as today (a `VaultException`'s message joins the `IOException` arm). The watcher then sees an echo and the Slate-owned `Created`/`Modified` event refreshes the tree, as a created note's does. If the owner answers WD5 "accept it", the chunk writes nothing here and closes #1508 with a comment recording the second sentence as AR-75's class.

**#1475 bullet 1 (WD7, first half).** `GraphConfigStore.Write` opens `AnchoredVaultStore.Open(_vaultRoot, createDirectory: true)` (keep the root in the ctor beside `_path`), reads the existing file through `ReadAllBytesBounded("graph.json", MaxReadBytes)` (absent → null, as today's `FileNotFoundException` arm), encodes through `GraphConfigEncode(config, existing)` and writes with `WriteAtomically("graph.json", bytes)`; a gone root throws `DirectoryNotFoundException`, which `GraphConfigWriter.Write`'s `IOException` arm already logs as `GraphConfigPersistFailed`. `Directory.CreateDirectory` is gone. `ReadExistingForTests` keeps its seam over the anchored read. **#1505 (WD6).** `LoadDirectoryLevel` returns, for a level whose listing is complete (`!truncated` and the provider page not truncated), `StalePinnedPaths`: the pins of that folder (`_pinned` filtered by `ParentPath == parentPath`) not among the listed file paths. `FilesSidebarViewModel` gains `PruneStalePins(folder, stale)`, run after the level publishes: skipped when `_settingsStore?.ReadOnlyReason is not null`, when `_pinsBehindFile`, when `_prunedFolders` (a per-session `HashSet<string>`) already holds the folder, or when a prune for it is in flight; candidates deduplicated and capped (mac's `sidebarStalePruneCandidateCap`; use 1,000, `MaxPinsPerFolder`); on a worker, each candidate re-checked as a definite ENOENT (`File.Exists` and `Directory.Exists` both false on `Path.Combine(root, candidate)`, no reparse point in the path — `HasReparsePointInPath`, `Import.cs:401`); back on the dispatcher, survivors removed from `_pinned` and persisted through `PersistPins()`; the folder joins `_prunedFolders` only when a write removed something (mac's "consumed by a committed mutation").
