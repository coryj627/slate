# W7-6 executable spec — F6 / Shift+F6 shell region cycling

Issue: W7-6 ([#1240](https://github.com/coryj627/slate/issues/1240)). Wave: [W7](w7_spec.md) (the UIA accessibility program). Depends on W7-5 ([#1239](https://github.com/coryj627/slate/issues/1239), [PR #1241](https://github.com/coryj627/slate/pull/1241)): the menu bar must already be out of the Tab order, and the empty tab control must already refuse focus. One PR. **Issue = unit of acceptance; PR = unit of review** (the W6 convention).

**Origin.** The first human NVDA field pass ([record](../reports/w7_5_nvda_field_pass_2026-09-20.md), Landmarks row) pressed F6, Shift+F6 and Ctrl+F6 four times and heard nothing: no binding exists. The owner's decision (2026-09-20) is the Win32 / Office convention — F6 cycles keyboard focus through the shell's regions, Shift+F6 cycles back. Today the only region movement is Ctrl+Alt+Arrows, which ping-pongs Files ⇄ editor splits ⇄ right-pane rail with no wrap and never reaches the menu bar or the status bar, and `slate.workspace.focusNextPane` / `focusPreviousPane` exist as chordless verbs that only walk editor split groups (`WorkspaceViewModel.FocusPane`, gated on `Groups.Count > 1`).

**Behavioral source (normative, in this order):** the owner decisions below → program decision 6 (canonical announcement artifacts produced in core) and the W7-2 four-place rule ([w7_spec.md](w7_spec.md) §B2) → the shipped boundary precedent (`WorkspaceViewModel.Layout.cs#FocusDirectionalPane`, `MainWindow.xaml.cs#ViewModel_WorkspaceFocusBoundaryRequested`) → [contract 39](../../39_at_navigation_contracts.md) and the [AT navigation map](../at_navigation_map.md). Mac has no F6 and navigates panes directionally only; this is a **recorded Windows-only affordance** (`MacCatalogParityTests.WindowsOnlyIds` already lists both verbs), not a parity target.

---

## 0. Owner decisions (2026-09-20)

- **D-1** F6 and Shift+F6 become the Windows chords of the EXISTING verbs `slate.workspace.focusNextPane` / `slate.workspace.focusPreviousPane`. The verbs widen from editor split groups to shell regions; the `Groups.Count > 1` gate goes. No second navigation mechanism.
- **D-2** Cycle order: **menu bar → Files pane → tab bar → editor → right pane content → right pane rail → status bar → (wrap) menu bar.** Shift+F6 is the exact reverse.
- **D-3** With files open, the tab bar and the editor caret are two stops. With no tab open, the tab bar stop is skipped and the editor stop lands on the empty editor pane region (announced as empty) — the note's "editor pane (empty) OR tab bar if files open".
- **D-4** A hidden right pane is **skipped**, never force-opened (unlike Ctrl+Alt+Right, which reveals it — that behaviour is untouched).
- **D-5** The status bar becomes a focusable, named region; its stop speaks the status text.
- **D-6** Each landing announces the region. Announcements are typed core events (decision 6, W7-2 B2), never `HostComposed` text.

## 1. Regions, in order

| # | Region | Landing element | Present when | Announcement (rendered by core) |
|---|---|---|---|---|
| 1 | Menu bar | `MainMenu`'s first top-level `MenuItem` (`FileMenu`), the same element Alt lands on | always (disabled under a modal surface — see §4) | "Menu bar." |
| 2 | Files pane | `FilesTree` (or `FilterResultsList` when the filter is active, the sidebar's own current stop) | always | existing `FilesRegionFocused` → "Files." |
| 3 | Tab bar | the `TabItem` container of the active tab in the active group (`FocusEditorPane` arm 4) | active group has ≥ 1 tab | existing `TabFocused` → "{filename}, tab {i} of {n}." with `prefix` "Tab bar. " |
| 4 | Editor | the active tab's input owner: `SlateTextEditor.FocusInputOwner()`; for a reading-mode tab its `ReadingSurface` (W7-7 R-10), landed once the note's projection is applied and current (no refresh of it in flight — a streamed note's refresh lasts until its last chunk) — an applied empty note included, at its start — and never while the surface shows the loading placeholder, a projection a refresh in flight is about to replace, or what a failed refresh left on screen. Readiness and failure are read before focus already in the surface: a reader inside a surface that is not ready (an in-place navigation swapped the note under them) is parked on the tab's item while the content arrives, then landed once on the applied content, and a surface showing a failure is no stop even with focus inside; for a canvas or graph tab the surface's focus landing (arms 1–3 of `FocusEditorPane`) — a canvas showing its Visual board lands on the renderer, the board's single focus stop (locked contract 34 D15), its node seated silently and brought into view. Every arm's landing is verified — focus in the stop, the document's request completed — before it counts; an arm whose content is still arriving (a reading projection, a canvas load, a graph whose load is in flight, which seats focus only provisionally) **holds** it: *Pending*, §4 | active group has ≥ 1 tab | existing `EditorPaneFocused` (unchanged copy), spoken once focus is in the stop: at once for a landing seated inside the press, when focus arrives for a held one, never for one refused, withdrawn or cancelled |
| 4′ | Empty editor pane | the `ContentPane` landmark (`AutomationLandmarkBorder`, already a named focusable Group) | active group has 0 tabs (replaces 3 + 4) | "Editor pane. Empty." |
| 5 | Right pane content | the shown leaf's first stop: the existing per-leaf landings (`ConnectionsLeafSurface.FocusAnchor`, `GraphInspectorSurface.FocusFirstStop`), else `FocusNavigationDirection.First` within the leaf body host (column 0 of the right-pane grid), else **skip to 6** | `IsRightPaneVisible` and the leaf has a focusable stop | existing `LeafPanelShown` → "{title} panel." |
| 6 | Right pane rail | `RightPaneLeavesList` (selected item) | `IsRightPaneVisible` | "Right pane panels." |
| 7 | Status bar | the `StatusBar` (`Focusable="True"`, `AutomationProperties.Name="Status bar"`, AutomationId `StatusBar`) | always | "Status bar. {status text}." |

Wrap: after 7 comes 1; before 1 comes 7. Skipped regions are simply absent from the ring for that press; the ring is recomputed on every press from live state (no cached order).

**Where am I** (the origin of a press): the focused element's landmark ancestor decides — `MainMenu` → 1; `FilesPane` → 2; a `TabItem` / `TabPanel` under `ContentPane` → 3; anything else under `ContentPane` → 4 (or 4′); under `InspectorPane` and inside `RightPaneLeavesList` → 6, else 5; under the `StatusBar` → 7. Focus on the window root, on an overlay, or nowhere → treat as "before 1" so F6 lands on 1 and Shift+F6 on 7.

## 4. Edge rules

- **Modal surface up** (`ModalSurface` non-null: palette, search, Quick Open, any sheet): F6 is a no-op — the menu is disabled and focus stays in the modal (the W5-2 rule that nothing opens beneath a sheet). The KeyBinding's command returns without moving focus; no announcement.
- **Menu bar stop and Escape**: landing on `FileMenu` puts WPF in menu mode. Escape leaves menu mode and WPF restores focus to the previously focused element, which is the region F6 came from. That matches Alt and is documented, not overridden.
- **Right pane content with no focusable stop** (a leaf whose body is a read-only notice): region 5 is skipped for that press, region 6 still lands — a reader is never stranded on an unfocusable notice.
- **Editor split groups**: F6 treats the whole editor area as one region; the active group's caret is the stop. Ctrl+Alt+Arrows remain the way between splits (unchanged).
- **Every landing answers one of three** (W7-7 R-10): *Landed* — focus is in the region now, and the ring speaks its line; *Refused* — focus the app cannot take (e.g. a landing whose `Focus()` returns false): fall through to the next region in the same direction, at most one full ring, then announce nothing and leave focus where it was; *Pending* — the region holds the landing for content still arriving (the editor arms, §1 row 4): the ring neither speaks nor moves on, and the press stays open on that one landing.
- **A held landing completes once, later.** Focus arriving in the stop speaks the region's line then, never before — the reader's own step into the held stop included, spoken when its content settles. A landing that cannot be completed while it and its target are still current — focus refused, only the reading view's load-failure notice arriving, the current reading model torn down before its apply with no rebind, the document letting go of its request unseated while its surface still shows the tab (a failure, or the document shut down under the live tab) — is a **delayed refusal**: the SAME press resumes from the held region in its own direction, the next region receives focus exactly once and speaks, and the held region is never spoken. A teardown that travels with a tab's close, a rebind or an unload (the tab or pane closed under the landing) is never a refusal: that move cancels the landing, below. An applied empty note is never a refusal: it is the note, landed at its start. A held landing that stops being wanted is **withdrawn** — no line, no resume, no focus move: the moment the reader leaves the element the press found them on (a one-way latch from that element — coming back does not revive it; a move WPF's recovery makes off an element that stopped being shown is followed, not latched), and the moment they move on INSIDE the held stop after entering it — entering is followed once (their own step in, or a graph's provisional seat; a press that finds focus already inside has had its entry), and after it only the document's own terminal seat, the move that completes its request, is followed (the surface declares it), so content arriving later never re-seats a reader who moved; synchronously when another route asks for the editor (the focus funnel behind every open, tab switch and pane move) or a modal surface opens; for the reading surface, when the view is hidden, unloaded or rebound to another note; for a canvas or graph, when the document replaces the request with a newer one or the surface leaves the tab (a tab switch rebinds the shared cell). A success arriving while a modal surface is open is never spoken. Each held landing ends in exactly ONE terminal transition, and **Cancelled** and **Refused** are exclusive: a rebind, an unload, the reader's leaving, a tab switch or a tab closure CANCELS it — the ring never resumes, nothing is spoken, and any later completion or teardown callback for it is stale; it is REFUSED (the same press resumes) only when it fails while it and its target are still current — the eventual focus refused, the load or refresh failed, the current model torn down with no rebind. A teardown's refusal is decided after the move it travels with, so a teardown plus a rebind or unload, in either order, is Cancelled.
- **A repeated press while a landing is held** (F6 or Shift+F6) **cancels** it — withdrawn as above, the document's request released, its late completion ignored — and starts one fresh traversal in the new press's own direction **from the held region's ring position**: from a held editor, F6 goes on to the region after it (the right pane's content stop; the rail when the shown leaf has no stop; the status bar when the pane is hidden) and Shift+F6 back to the tab bar, whichever neighbour the held press came from. A landing its region already let go of, or one whose reader has moved — even between two stops of one region — holds no position: the press starts from where focus is. Cancellation, never queueing: one press's landing is open at a time.
