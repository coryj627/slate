## Not reached, and why

- **B6, Cancel in the status bar (`CancelTrash`).** Two attempts in launch 2. In attempt 1 the recycle confirmation was a Slate window ("Move “bulk” to the Recycle Bin?", buttons Cancel and Move to the Recycle Bin), not the message box the driver expected, so its route keys moved inside the box only. In attempt 2 the confirm was pressed at 13:34:07.092; "Moving items to the Recycle Bin…" was logged at 13:34:07.182 and "Moved bulk to the Recycle Bin." at 13:34:08.079, so the trash of 200 notes ran about 0.9 s. The keys had landed on the File actions header; Shift+F6 twice reached the status bar at 13:34:08.972, after Cancel had gone. A larger folder would outlast the trip; it was not tried, to keep thousands more fixture files out of the shared Recycle Bin.
- **B11, `MoveToRetry`.** Unreachable by keys, as the spec says: Move To fails to load only on a refused listing page (#2012's race). Not tried; it rests on reading.
- **C6's trigger.** Renaming `Queries.base` on disk with the keys on Open drew "Files refreshed. 1 new or changed, 1 removed." but the Queries leaf did not refresh: its base files list kept the stale `Queries.base` row selected and Open stayed on, so the group never went off. Pressing that Open afterwards (13:48:34.899) opened a Queries tab whose base could not be loaded ("Retry, button, Attempts to reopen the Base at its current path.").
- **B5, attempts 1 and 2.** Attempt 1's folder picker never closed (Alt+S did not press Select Folder; Escape cancelled it). In attempt 2 the picker closed and the import ran (974 of 2,000 notes 5 s in, all 2,000 by 17 s), but the keys had landed on the main window and Tab from there walks the Files toolbar, so Cancel import was not reached in time. Attempt 3 took F6 twice and Shift+Tab twice and reached it in 1.6 s (the table).

## Heard that the spec did not expect

Reported as heard; nothing was fixed. Whether each is CD11's class (CB-17b) or a find of its own is the principal's call.

1. **After Import…'s box is cancelled, the keyboard is dead until Alt (B4).** Space on Import… at 13:19:04.590 opened "Import Files and Folders"; Import… went off while the box held the keys (13:19:04.717). Escape at 13:19:07.047 closed the box; UIA's focus went to the main window's HWND (class `HwndWrapper[SlateWindows;…]`, 13:19:07.094) and Import… came back on 30 ms later (13:19:07.123). NVDA logged "escape" and nothing else. Then Ctrl+O at 13:19:51.576 and 13:20:25.516 drew only "ctrl+o" (no Quick Open opened), and F6 at 13:20:22.286 drew only "f6". Alt at 13:20:44.052 gave "n001 — cb17a-L1 — Slate, window" / "Slate menu, collapsed, Alt+F, 1 of 1", and Escape at 13:20:45.637 returned the keys to "File actions, grouping, expanded" / "Import…, button". By the recorder, the window restored focus while Import… was still off, and no WPF element took the keys.
2. **The keys rest on the main window after other sheets and pickers close.** Escape from the template picker opened from the launcher left the keys on the window element with nothing but "escape" logged (A1 at 13:12:23.569, A2 at 13:12:49.038, A3's setup at 13:13:05.347); F6 still worked there. Settings, by contrast, gave the keys back to Quick Open… (13:13:21.080). After B5's folder picker closed, the keys rested on the window element too ("cb17a-L3 — Slate, window", 13:42:48.570); Import… was off then (busy).
3. **Bulk Rename leaves its sheet open with the keys behind it (C1, C2).** Known from #1866; this run adds that the keys stay there with the sheet still modal and open, so the next printable key goes into `a.md`'s text (from the editor) or moves the tree (from the Files tree). 4. **The Queries leaf does not follow an on-disk rename of a base file (C6).** The stale row stays selected with Open on; Open then opens a base that cannot load. Outside CD11's class.
5. **Tab from a Files tree row stops on the main window (silent).** From a row, Tab put UIA's focus on the main window element with only "tab" logged (13:25:40.908, 13:31:24.757); the next Tab reached "Workspace tabs, tab control". Outside CD11's class.

## Limits of the method

- The recorder watches `IsEnabled` only under the main window: popups (menus, the editor popover, message boxes) are not covered.
- WPF raises an `IsEnabled` event to UI Automation only for a change that survives to its layout pass, so a control turned off and on again within one dispatcher operation (the reading's Rename, Move to… and selection-verb case) is invisible to the recorder and to NVDA alike. B12 and B14 show no off; that is not evidence the off did not happen.
- The focus poll runs every 40 ms; the order of a poll line and an event line closer than that is not meaningful.
- A logged `Speaking` line can still be cut off by the next one.
